# 随机组卷算法设计

## 1. 目标

随机生成不同测试卷，同时保证不同用户结果可比较。

## 2. 禁止方式

禁止：

```
从全部题目随机抽 N 题
```

原因：

- 可能缺失重要维度
- 不同用户测量目标不同

## 3. 桶驱动抽题（依赖分桶索引）

默认试卷为 **50 题**，从分桶索引 `questions.index.json` 的组中抽取：

```
must (5) + experimental (1) + 常规 10 维度 (44) = 50
```

流程：

```
选择测试长度（默认 50）
↓
must 组桶驱动抽 5 题
↓
experimental 组桶驱动抽 1 题
↓
其余 10 个维度组均分剩余名额（每维度 4~5 题）
↓
每维度组内「先抽桶、再在桶内随机取题」（不重复）
↓
组内题数不足时按 fallback 补齐；最后整卷去重校验
↓
生成测试卷
```

## 4. 桶驱动抽题算法

对某个组（m 桶、d 题）抽 n 题（d >= n）时：

1. 先抽 k = min(n, m) 桶（不放回随机）；
2. 收集这 k 桶的全部题目作为候选；
3. 候选不足 n 题时，**重复抽桶**（从剩余桶继续随机抽取）补充，直到候选 >= n 或所有桶都被抽过；
4. 从候选中随机取 n 题，**不重复**（同一题不出现两次）。

若组内总题数 d < n，则抽出该组全部可用题，不足部分按 **fallback** 补齐
（优先级：维度组 → must → experimental）。整卷最后**校验是否有重复题**，若有则按 fallback 重抽该题。

> 抽题只依赖分桶索引中的**桶文件位置与题数**，按需懒加载桶文件，不加载全量题库。

## 5. 配额说明

- **must**：分桶索引中 must 组（10 桶、40 题，`Must_Bnk01~10.json`），桶驱动抽 **5 题**，用于跨用户结果锚定；
- **experimental**：不分桶（`Exp_Bnk01.json` 单文件、20 题），固定抽 **1 题**，用于数据试运行；
- **其余 10 个维度组**：均分剩余名额。默认 50 题时剩余 44 题，随机挑 4 个维度各抽 **5 题**、其余 6 个维度各抽 **4 题**。

> 不再按难度（easy / medium / hard）分层抽取。
> 若请求非默认长度，`must`（5 题）与 `experimental`（1 题）保持固定，其余维度组的配额按剩余名额等比例缩放、余数随机分配。

## 6. 题目池要求

每个维度组应拥有多个同权重不同情境的问题（即分桶索引中的每桶 4 题）。

例如：

```
privacy -5
├── 健康记录公开
├── DNA出售
├── 私密聊天公开
└── 记忆读取
```

## 7. 后续优化

根据用户数据调整：

- 题目出现频率
- 区分度
- 权重准确性
